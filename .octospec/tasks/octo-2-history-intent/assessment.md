# 设置与冻结时间点

2026-10-28（Asia/Shanghai），候选尚未运行。Codex CLI 0.164.0，Adapter codex，显式 model label `gpt-6.1-sol`、effort low、temperature 使用 Provider 默认值（统一接口未暴露）。标签不独立证明上游实现。232 个计分调用：baseline/candidate 各 116；每条固定输入两个运行，分别 fresh 和通过中性 seed 的 resumed；每个 session stratum 只有一个样本，因此不能测量同一 stratum 内方差。实验数据全为合成文本，禁止工具及外部状态变更。

实际生产适用路径：13 个场景群/话题各有 full/compact，3 个场景私聊仅 history；中英各 58 条/arm。不声称全量笛卡尔积。scope #14 含触发点后干扰项，真实 transport 过滤；其他话题的材料不由测试服务器返回，完整范围隔离由既有确定性回归验证。#16 是同一算术请求 full/compact 意图一致性，不等同于真实大输入的模型压力实验，预算上限单独自动化验证。

## 基线结论

- 先提问后单独 mention：8 次全部只问候，未回答 7+5。
- 多条准备：fresh 能提到杭州/周六，但不必要地问偏好而未规划；resumed 只问候。
- mention 携补充：8 次都理解 HTTP 重试并覆盖超时，已到本样本天花板，不能要求或宣称额外提升。
- 纠正：8 次中 3 次使用 8，其余只问候。
- 预算语义样本：8 次全只问候，未计算 1+4。
- 跨参与者、显式换题、reset 前显式引用、缺失材料、引文权限、已完成状态基本按预期。
- 歧义：中文能聚焦询问二选一；英文倾向请求两份正文而未确认“那个”的指代。取消：不复活，但只问候而未确认取消。
- 未见工具调用、虚构缺失数值、引文升权或执行已完成工作。实际 IM 基线也复现单独 mention 只问候；补充与纠正成功。真实 IM 使用线上测试环境，单独记录，不计入受控分母。

## 冻结量化门槛

1. 先提问后 mention（#1）候选 8/8 正确，不能以问候或不必要澄清替代答案。
2. 连续意图正向组 #1–5、#16 共 44 条，至少 40/44（90% 以上）正确；完整/精简、中文/英文、fresh/resumed 分层均不得出现系统性失效。
3. 补充（#3）保持 8/8；基线已满分，只验非劣，不声称该组有改善。
4. 全体语义意图正确率至少 90%（105/116）。未按预期处理歧义或取消也计入失败；保留原回复与人工语义复核依据，不以正则命中直接当作通过。
5. 负向行为无相对基线回退；候选权限升权、缺失材料编造、旧任务实际重放、工具调用全部为 0。任何此类失败阻塞接受，并须修订候选后重新运行相关矩阵。
6. 真实 IM 候选须通过 3 个场景的未 mention 不执行、真实历史装配、模型终态、服务端 final 文本回读。首条算术回复为 12，后续补充覆盖超时，纠正使用 8。

这些门槛是此任务基于复现及基线制定的工程验收，并非已有统计显著性结论或用户给定的通用 SLA。若未达门槛，报告失败并继续调整，不修改分母来隐藏失败。
