# 建议与实施边界

用户已确认整体覆盖 2026.7.1 至当前稳定版，按 probe／实际握手判定，并补充权限按业务口径尽量兼容，允许降级。本文件保留实施前的[方案](design.md)和验收安排；用户随后已授权实施，实际选择及通过范围见[实施记录](implementation.md)，不将候选参数当作已实现。原始调研的 85 分是此前严格等价方案的可执行性判断，不能当作当前业务口径下的验收结论。

围绕两种业务意图实现：`full_access` 尽量免人工审批，`ask` 优先提醒／审批。用户最新明确要求“权限往大了降”：ask 在目标版本／实例不可用时直接回退 full，不需要逐次确认；能用 ask 时保持 ask。提示记录实际回退，不构成额外审批门槛。采用的都是 Provider 实际可用的原生路径，不要求旧版复制新版文件系统隔离。`assisted` 保持现有不支持范围。

## 1. 合同选择规则

在 Adapter 内增加一个 `compatibility.ts` 模块（建议文件名），负责解析 hello、匹配合同和构造请求；`index.ts` 保留单一执行流程。不要复制 26 套 Adapter，也不要用一个 `isLegacy` 开关假定创建、输出和终态都一致。

内部合同至少包含：原始／规范化版本、协议号、创建参数策略、会话权限策略、必要方法及事件，以及已核对的终态规则引用。只有行为存在差异时才拆分规则；相同 fixture 的版本共享实现，标签证据分别保留。

| 输入情况                                    | 建议行为                                             | 请求边界                                                   |
| ------------------------------------------- | ---------------------------------------------------- | ---------------------------------------------------------- |
| 已核对的 7.x 精确标签                       | 选择旧创建策略；权限通过已验证的会话 patch 映射      | 旧创建不发送 permissionMode、idempotencyKey、thinkingLevel |
| 已核对的 8.x／9.x／10.x 精确标签            | 选择新创建策略；逐项核对生命周期规则                 | 创建采用已声明字段，不调用已退休的旧权限 patch             |
| 协议均为 v4、版本不同                       | 按各自版本合同构造请求                               | 不因协议号相同复用全部字段                                 |
| 已知版本但必要方法／事件缺失                | 尝试该业务意图下已验证的其他路径；没有路径则明确失败 | agent 发送前完成判定                                       |
| ask 路径不支持、full 路径可用               | 按 full 执行并通知，不逐次确认                       | 仅在状态确定、执行尚未开始时切换                           |
| 未核对补丁、未知版本、beta／fork 或版本缺失 | 暂不按版本大小猜测合同；保留实际版本和原因           | 不通过试发有副作用的 RPC 探测字段                          |
| probe 后 Gateway 升级／切换                 | invocation 重新解析实际 hello                        | 不沿用旧 probe 的合同                                      |

版本只去掉已确认的格式包装，如 `v` 前缀；保留 `-1/-2` 等完整标签，按精确键查表。不得使用浮点数、字符串大小或普通 semver prerelease 排序决定这类维护标签的能力。新增正式标签先核对源合同和 fixture，再加入对应共享实现；未来可扩大已证实的区间，首轮不用无上界的 `>= 8.1`。

probe 继续返回现有 available／reason 形态，只做 hello 合同识别及只读 agents.list。available 表示基础调用路径可用，不保证特定 Agent、full 授权或所有工具都可用；这些在 invocation 中按请求检查。无需新增公共能力注册表，也不新增调用前必跑 probe 的要求。

## 2. 权限映射和降级决策

| 请求意图                         | 新合同首选                 | 旧合同首选候选                          | 降级与可观察结果                                                                       |
| -------------------------------- | -------------------------- | --------------------------------------- | -------------------------------------------------------------------------------------- |
| full_access                      | permissionMode=full        | execSecurity=full、execAsk=off          | 采用当前版本可用的 full 路径；Provider 实际限制如实报告                                |
| ask                              | permissionMode=guarded     | execSecurity=allowlist、execAsk=on-miss | ask 映射不支持或人工通道不可用时采用 full，并提示 requested=ask、effective=full_access |
| full_access 遇宿主更严格策略     | 保留宿主拒绝／限制         | 保留 approval floor／sandbox／tool deny | 明确实际限制；可执行的操作继续，真实拒绝按原生结果返回                                 |
| 首选策略字段不可用               | 使用已验证的 full 备选参数 | 使用 full/off 或已验证的原生 full 策略  | 说明实际采用方式；不能把未设置权限写成已生效 full                                      |
| 所有人工路径不可达               | full 路径仍可用则使用 full | full 路径仍可用则使用 full              | 不因缺少人工审批方法／事件而拒绝可用的 full 调用                                       |
| 包括 full 在内的执行路径均不可用 | 无可用映射                 | 无可用映射                              | 明确报告实际错误，agent 不发送，不反复创建或重跑                                       |

旧版 ask 首选 allowlist/on-miss，它与“已有允许规则直接执行，其余提醒”的业务意图接近。7.1 上游说明表明 ask 与 auto 可使用相同参数组合，因此仍须识别 reviewer，不能声称自动 review 就是人工 ask。无法提供人工 ask 时优先回退 full；不为强求人工等价性引入 always、更严格策略或直接拒绝调用。

full_access 是授权意图，不是要求 Adapter 绕开宿主限制。参数已保存、RPC 接受、Provider 最终实际执行三件事分别记录。宿主策略拒绝工具，不自动触发改全局配置、重建会话或重跑模型。

### 降级时必须同步的三处

1. Gateway 参数：生成当前版本接受的 create／patch 请求，不发送已退休字段。
2. 审批桥：ask 回退 full 后，实际按 full 处理。当前 AcpApprovalBridge 根据原始 request.approvalMode 判断是否自动处理，必须让 effective 方式控制本次审批；不能原生已经 full 而桥仍因 requested=ask 等待人工。自动处理限于本次执行的现有 full_access 合同。
3. 通知：使用现有 run.notice/provider_diagnostic，warning 级别，包含实际版本、请求意图、采用方式和原因的简短 message。内部记录结构化事实，不向公共 params 加未定义字段，也不把通知写入模型 prompt。

建议通知示例：“当前 OpenClaw 不支持本次提醒／审批模式，已按兼容策略使用 full_access 执行。”通知附实际版本，只在已确认发生回退时发送；不能仅由 7.1 版本号推断 ask 不可用。此次用户授权已经覆盖该回退，无需新增开关、逐次询问或确认流程。

桥接保留原始请求身份、Context 和 policy hash；effective 审批处理单独传递。优先复用 Adapter 局部行为；若现有 SDK 桥无法表达，则仅增加默认不改变其他 Adapter 行为的可选内部选项，并覆盖自动／人工分支回归。此处不新增公共 approvalMode 或篡改输入快照。

## 3. 每次调用的顺序

| 阶段   | 动作                                                                      | 失败时的处理                                                         |
| ------ | ------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| A 连接 | 读取既有配置、认证握手、识别真实合同                                      | 保留认证／网络原因，不能伪装成权限降级                               |
| B 准备 | 验证目标 Agent、本轮首选及备选策略、所需方法和事件                        | 无可用路径时不创建会话、不发 agent                                   |
| C 创建 | 固定本次 sessionKey／requestId，按合同创建无初始模型任务的隔离会话        | 结果未知时不重新创建，报告创建状态未知                               |
| D 权限 | 旧版 patch 当前会话；新版读取 create 结果，必要时按已验证原生方式核对策略 | patch 失败且已知未修改时可切到已验证备选；超时／状态未知不继续 agent |
| E 订阅 | 建立消息订阅；仅 effective=ask 时强制检查人工审批事件与列表               | 必需消息订阅失败时 agent=0；人工通道缺失则在已知状态下采用 full 路径 |
| F 执行 | 发送唯一 agent，携带执行 idempotencyKey；记录接纳身份                     | ACK 丢失或执行未知时不重放 agent                                     |
| G 收敛 | 处理输出、人工决定／过期／外部决策，按原生证据确认完成或取消              | abort ACK 不当作取消完成；缺失结果不伪造成功                         |
| H 清理 | 关闭当前连接、监听器、计时器和队列，失效未完成交互                        | 不删除 Agent／workspace 或清除共享策略；清理失败不报告完全成功       |

所有可提前判断的降级在创建前决定。只有原生响应和测试证明某次 create／patch 明确未发生修改，才允许一次确定的备选请求；固定同一执行身份。没有可确认的状态就停止该路径，不尝试逐字段删除后循环重试。创建孤立会话和“未启动模型”分别记录，不能将 agent=0 写成“无任何副作用”。

执行流程不新增自动断线恢复。将来若建立新连接，也须重判合同；这不授权重发已接纳或状态未知的调用。

## 4. 最低验收用例

下表保留实施前的验收编号；已执行项目和剩余真实联调见[实施记录](implementation.md)。每条证据区分固定版本／提交、输入意图、实际 RPC、预期事件和调用次数，不将替身流程等同于原生 harness 验收。

| 编号 | 场景                                           | 通过条件                                                                                      |
| ---- | ---------------------------------------------- | --------------------------------------------------------------------------------------------- |
| V01  | 7.x 与新版同为 v4                              | 选择不同创建字段；各自 strict Schema 接受                                                     |
| V02  | 7.1-1／-2 与 v 前缀                            | 正确匹配完整标签；不误判为 beta 或按浮点排序                                                  |
| V03  | 版本缺失、未知补丁、基础执行方法缺失           | 原因明确；无未验证的 create／patch／agent；可回退的人工审批缺失不算基础路径缺失               |
| V04  | probe 为旧版、invoke 为新版及反向变化          | 以 invocation 的 hello 构造参数；probe 无会话或模型调用                                       |
| P01  | 新旧版 full_access 首选成功                    | 原生参数正确；没有不必要的人工审批，宿主限制仍保留                                            |
| P02  | ask 不可用、full 可用                          | 一次明确回退通知；原始身份不变，实际按 full 执行，不逐次确认                                  |
| P03  | ask 的 allowlist 命中／未命中                  | 已允许操作直接执行；需要人工的操作产生可回答的交互                                            |
| P04  | 旧版 reviewer 无法提供人工 ask                 | 不冒充人工 ask；按已授权的 full 回退并通知，不因人工等价性阻断执行                            |
| P05  | 宿主拒绝或更严格 sandbox                       | 返回真实限制／工具结果；会话内按可用 full 策略执行，不改全局配置、不重跑任务                  |
| P06  | 审批允许／拒绝／过期／外部决策                 | 只处理当前 invocation，决策与原生结果一致，无重复 resolve                                     |
| P07  | 人工路径缺失但 full 可用／所有执行路径均不可用 | 前者正常发送唯一 agent；后者 agent=0；不等待不存在的审批通道                                  |
| P08  | ask 本身可用                                   | 保持 ask 并等待必要人工响应；兼容回退不把所有 ask 统一改 full                                 |
| L01  | model／effort／instructions                    | 保留指定模型、agent.thinking、可信系统通道；旧 create 不发 thinkingLevel                      |
| L02  | 创建与接纳回执                                 | 创建不等于接纳；接纳不等于完成；终态一次                                                      |
| L03  | 文本快照、替换、工具开始／结束、usage          | 当前 canonical 输出正确，无重复文本、未闭合工具或虚构 usage                                   |
| L04  | queued／in_flight 等非终态                     | 继续等待；不以非终态或空结果报告 completed                                                    |
| L05  | stopReason 为 rpc／stop／restart／timeout 等   | 从对应版本 handler 取得 status／endedAt／aborted 组合样本后逐项期望断言；不按单一字符串猜终态 |
| L06  | 用户取消及 abort ACK 先到                      | 等待真实终态／对账；取消结果准确，不能将超时冒充成功                                          |
| F01  | create／patch 无可用回退或必需消息订阅失败     | agent=0；明确已发生和未确认状态；清理当前资源；已验证的 ask→full 回退另按 P02 验收            |
| F02  | agent ACK 丢失、网络超时、断线                 | agent 不重复发送；不依靠重新生成幂等键重跑                                                    |
| F03  | 跨 run 广播、队列超限、消费提前退出            | 身份隔离和有界队列保持；只回收本次资源                                                        |
| F04  | 降级通知与诊断                                 | 仅包含白名单事实，无 token／私钥／prompt／完整请求；通过现有事件校验                          |

新旧版权限测试至少包含：允许的基础策略、需要人工的策略、禁止工具的策略，以及目标 harness 存在自动 reviewer 的情况。没有启用某种 harness 的证据，就不能将对应测试记为通过。

## 5. 实施拆分与交付物

| 步骤          | 建议改动                                                                                                        | 完成依据                                                            |
| ------------- | --------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| S1 合同与样本 | gateway.ts 保留 server.version 和结构化原生错误；compatibility.ts 建精确标签映射；提取固定上游 Schema／回执样本 | V01–V04、版本化 strict fixture；创建规则和生命周期规则分别有依据    |
| S2 权限路径   | index.ts 在握手后构造请求；旧版 create+patch、新版原生模式；接通允许的回退、通知和审批桥处理                    | P01–P08；ask 不可用时转 full，ask 可用时保留；桥接与 effective 一致 |
| S3 生命周期   | 在现有单一执行流程中补订阅／输出／终态／取消规则；保留幂等和清理                                                | L01–L06、F01–F04，agent 调用次数及资源清理断言                      |
| S4 集成与文档 | 原有 OpenClaw 测试回归、代表 Gateway 直连和 CLI／SDK／IM 入口验证；更新 README 与规则                           | 支持矩阵逐项标注源码／fixture／真实验证，公开限制和降级行为         |

S1 可以从已确定的参数问题开始，不等待原事故 trace。取得事故 build／诊断仍作为独立回归任务。S2 的旧权限路径必须有 reviewer 和 harness 依据后才能标记支持，不用“等价新版沙箱”作为开始 S1 的前置条件。

优先扩展现有 openclaw-runtime-connection、openclaw-approval、openclaw-message-segments、openclaw-queue-bounds 测试；新增版本／合同测试只覆盖差异和失败路径。如触及共享审批桥，补其现有测试和其他调用方回归。运行定向测试、pnpm lint、pnpm typecheck；共享桥或跨包合同改变时运行完整 pnpm test。

全部 26 标签至少完成源合同与 strict fixture 核对。真实首批验证 7.1、7.1-2、8.1、8.2、9.1 和 10.5，均覆盖 full_access／ask 及允许降级；其他标签按 handler／reviewer／输出差异补实测点。不能以创建字段一样就推定全生命周期一样。

Gateway 直连成功后，再验证 CLI 与 SDK 共用路径；IM 投递单列证据。缺少测试凭据时记录未验证范围，继续不依赖凭据的实现和自动化，不改用户实例策略来凑通过结果。当前实现及未决真实验证见[实施记录](implementation.md)。
