# 已确认的整体方案

兼容目标为 OpenClaw `2026.7.1` 至当前稳定版，覆盖会话创建、执行、流式输出、审批、取消、终态和资源回收。不能只修复创建参数报错就视为整体兼容完成；26 个已核对标签是当前证据基线，后续稳定版继续验证和维护对应合同。

在 `octo-runtime-adapter-openclaw` 内增加一个小型合同解析和参数映射模块，共享现有执行及事件处理流程。以真实握手的 `server.version`、协议号、方法及事件集合选择已核对合同；如以后确认上游提供字段级合同查询，再优先使用该原生机制。本轮没有发现可以直接替代版本表的字段级协商接口；`config.schema` 查询的是配置，不能冒充 RPC 参数 Schema。

用户已确认以上整体目标和基于 probe/握手的兼容判定方向，并明确权限是业务口径，主要为 `full_access` 和提醒／审批两类，允许按版本能力降级。随后已授权实施；本文件保留方案及候选路径，实际实现和验证以[实施记录](implementation.md)为准。版本适配由 OpenClaw Adapter 内部负责，调用方继续使用统一 Runtime 接口，不增加公共能力目录或要求调用方提交 Provider 版本。具体决策、调用顺序和验收见[细化实施计划](implementation-plan.md)。

判定分为以下几项，任何一项都不能独立替代完整合同核对：

| 依据                       | 判定责任                                                               |
| -------------------------- | ---------------------------------------------------------------------- |
| 握手协议号                 | 选择可解析的连接协议；目前已核对版本均为 v4，仍需进一步区分版本合同    |
| `server.version`           | 匹配经源码、fixture 和行为验证的版本合同，确定字段及语义映射           |
| 实际方法和事件集合         | 交叉核对目标实例是否满足所选合同，发现裁剪、权限限制或实现差异         |
| 已验证的 Schema 与执行行为 | 确认参数接受、权限效果、事件、取消和终态；声明支持某字段不等于语义等价 |

## 1. 两类创建请求

| 合同                       | 创建参数                                                               | 思考强度                                                         | 权限处理                                          | 创建重试                   |
| -------------------------- | ---------------------------------------------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------- | -------------------------- |
| 已核对的 7.x 标签          | key、agentId、可选 model                                               | 已有 agent.thinking；必要时按旧合同 sessions.patch.thinkingLevel | 隔离会话上的旧版 exec 策略适配候选，见下一节      | 默认不重试；无创建幂等字段 |
| 已核对的 8.x/9.x/10.x 标签 | key、agentId、permissionMode、idempotencyKey、可选 model/thinkingLevel | 保留已验证的 create 与 agent 映射                                | ask→guarded、full_access→full，核对授权及执行语义 | 首轮实现仍不做通用重试     |

创建参数在 hello 后生成，不能在尚未知晓 Gateway 合同时固定为新版对象。显式保留 agent 的 idempotencyKey，不能因为旧版创建不支持该字段而把执行幂等也移除。model、extraSystemPrompt、deliver:false 保留原意；禁止用 prompt 文本模拟权限或控制字段。

字段分组不表示整个 8.1 至 10.5 的所有行为相同。版本表先列出明确标签；新增补丁、fork 或缺失版本不能仅凭版本大小自动归入最新合同。7.1-1/-2、7.33/34/35、8.33/34/35、9.33 已单独检查，不用浮点数或普通字符串比较版本。

## 2. 两种业务权限意图与降级

本任务不要求旧版完整复制新版 `guarded` 的文件系统边界。业务模式对应现有 Runtime `approvalMode`，与 OpenClaw RPC 中同名或近似的原生字段分开；不新增公共权限枚举。`ask` 优先映射人工提醒／审批；用户已明确授权，当对应版本或目标实例不支持该路径时，可以按 `full_access` 执行，权限向大兼容，以旧版可用为优先。`full_access` 采用 Provider 和宿主实际允许的免人工审批路径。

| 业务意图      | 已核对新版首选                 | 7.x 首选候选                                                 | 允许的降级                                                             |
| ------------- | ------------------------------ | ------------------------------------------------------------ | ---------------------------------------------------------------------- |
| `full_access` | 创建 `permissionMode: full`    | 隔离会话 patch `execSecurity: full`、`execAsk: off`          | 保留当前版本可用的 full 路径；实际宿主限制如实报告                     |
| `ask`         | 创建 `permissionMode: guarded` | 隔离会话 patch `execSecurity: allowlist`、`execAsk: on-miss` | ask 映射或审批通道不可用时，直接采用上述 full 路径并通知，无需逐次确认 |

7.x 的候选参数有上游字段和模式说明依据，但仍需核对实际 harness、自动 reviewer 及宿主策略。`allowlist/on-miss` 也可能用于 auto-review，不能只看参数保存成功就声称人工审批已生效；若没有可用人工路径，按用户已授权的 full 回退处理，不以此阻断版本支持。

本任务的“降级”指功能兼容回退，不表示权限必须收紧。明确采用 `ask → full_access` 的方向；它只在 ask 不可用时触发，不能将所有原本可用的 ask 调用统一改成 full。新版没有的文件边界不作为旧版调用的额外前置条件，也不声称旧版因此获得新版沙箱能力。该授权限于本任务 OpenClaw Adapter 的逐调用兼容，不扩展为其他 Provider 或全局策略变更。

每次调用分别记录 requested 意图、选定的 effective 处理方式、原生参数及降级原因。通过现有 `run.notice/provider_diagnostic` 发送一次有界、脱敏的降级说明；不能仅记录日志，也不能把“请求已接受”写成“宿主所有限制已解除”。不增加公共事件字段，具体依据写入内部诊断及现有 message。

现有 `AcpApprovalBridge` 按原始 `approvalMode === full_access` 自动选择放行。ask 回退为 full 时，Adapter 的实际审批处理必须同步按 full 执行，不能继续因原始 ask 等待人工。若 Provider 仍产生可由本次执行处理的审批，按已有 full_access 合同自动回答本次请求，不新增持久授权。保留原始请求、Context hash 和 invocation 身份，内部单独持有 effective 处理方式；若需扩展桥接选项，默认行为保持原样，并为其他 Adapter 增加有意义的回归覆盖。

优先回退到 full 继续执行，不因“缺少 permissionMode”“ask 审批不可达”或“与新版 guarded 不完全相同”直接拒绝。只有包括 full 在内的已知执行路径均不可用、参数合同不明或出现真实认证／执行故障时才明确失败。审批方法／事件仅在 effective=ask 时作为必需项；effective=full 时不因缺少人工审批通道判失败。原生工具被宿主策略拒绝应按真实工具／执行结果报告，不能一概归为版本不兼容；拒绝执行仍不算旧版支持完成。

不写 `config.patch`、不替换全局审批文件、不自动运行 doctor 或升级 Gateway。`assisted` 继续按现有合同明确拒绝，除非另有需求和独立验证。

## 3. 共用生命周期与结构化错误

保留当前每 invocation 一条连接、有界队列、runId/sessionKey/approvalId 过滤及原身份对账。创建、订阅、执行接纳与终态分别处理；兼容代码不得重放未知执行。

- hello 类型和内部合同保留实际 server.version；诊断分别记录用户报告版本与实际探测版本。
- 原生错误保留 code、method 及经过白名单脱敏的验证字段，附所需语义和可执行建议。不要记录 token、设备私钥、prompt、完整请求或全量原始 details。
- 完成与取消按已核对的 status/endedAt/stopReason/aborted 组合归一化。补充 rpc、stop、restart、timeout 和非终态样本，不把 abort ACK 当作取消完成。
- exec 审批的列表/事件/原始决策保持当前桥接。外部决定和过期只退休当前交互，不重新发决策；只回答本轮所属审批。
- 输出先取得版本样本再适配。保持当前 OpenClaw canonical-only 范围，核对文本替换、工具结束、usage 和终态；不新增 native 公共接口，不凭新字段存在就声称支持。

按合同预先选定参数和 ask→full 回退路径，首轮不实现通用重试。仅当源码和 fixture 证明原生响应明确表示创建／策略修改尚未发生、错误专属于 ask 路径且 full 路径可用时，允许一次固定身份的回退请求。认证失败、网络超时、会话创建状态未知、agent 接纳未知和执行错误都不能触发重新创建或 agent 重放。7.x 的 key 重用不自动等同于新版幂等合同。

## 4. probe 与实际执行共用判定

probe 和 invocation 使用同一个 Adapter 内部合同解析器，流程为：连接并取得真实 hello → 识别协议号和 `server.version` → 核对方法及事件 → 匹配已验证合同 → 得到内部参数及生命周期映射。合同决定仅适用于当前连接；不在公共 Context 或调用方保存版本分支。

probe 复用该解析器及现有只读 agents.list，结果表示本次连接和合同检查，不创建会话或启动模型，也不宣称已实测所有权限模式。认证可连、基本调用合同满足、本轮所需权限语义满足应分别判断。

实际 invocation 在每次新连接或重连后重新读取握手并解析合同，在组装请求前检查本轮所需语义。probe 结果不能直接作为后续执行的授权依据：Gateway 可能在两者之间升级、重启或切换。重连后的重新判定也不构成重放已接纳或接纳状态未知执行的许可。

已核对版本匹配到具体合同后才组装执行请求，并按本轮业务意图选择首选或允许的降级路径。版本缺失、格式不明或未来版本在无法建立参数及审批处理依据时，执行前报告 `OPENCLAW_COMPATIBILITY_UNSUPPORTED`（建议内部错误标识，尚未新增公共协议码），带实际版本或 unknown、RPC、字段／业务意图及说明。

新版本原生协商若有明确证据，可在 Adapter 内放宽未知版本路径，但不能仅依赖方法名。参数缺失先匹配其他已验证映射或允许的降级；所有已知路径均不能满足业务意图时才报告未支持并继续跟踪。

## 5. 建议实施顺序和验收

| 阶段 | 工作                                                                              | 通过依据                                                                         |
| ---- | --------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| M0   | 固定两类业务意图与降级规则；核对旧版 patch、reviewer 和 harness；现场取证独立跟踪 | 7.1 首选及降级分支有源码／fixture 依据；不等待事故 trace 才开始确定性修复        |
| M1   | 实现内部合同解析、版本识别和两类请求构造；保留结构化原生错误                      | 严格版本 Schema 接受全部实际请求；未知版本在副作用前失败                         |
| M2   | 接通权限意图映射、降级通知和桥接策略，核对思考强度／订阅／终态／取消              | ask 不可用时按 full 执行并通知，不等待不存在的人工通道；fixture 覆盖真实生命周期 |
| M3   | 本地回归及故障注入                                                                | 校验错误、断线、接纳丢失时 session/agent 调用计数无重复；审批/队列/输入回归通过  |
| M4   | 真实代表版本与文档                                                                | 7.1、7.1-2、8.1、8.2、9.1、10.5 的基本执行、权限和取消；其他标签按协议差异补点   |

自动化使用上游固定提交提取的完整 strict Schema fixture，不再只验证 method 名和自造返回对象。至少包含三种旧字段拒绝、新字段接受、patch Schema 接受但实现退休、model/effort/instructions、审批生命周期、取消对账、未知版本、超时和无重复执行。

合同判定还需覆盖：同为 v4 的不同版本选择不同参数；probe 与 invocation 之间服务端版本变化时按实际连接重判；重连后合同变化不重放未知执行；ask 不可用但 full 可用时继续；人工审批缺失不阻断 full，所有执行路径均不可用时才不发送 agent；probe 始终不创建会话或启动模型。

产品实现后运行定向 OpenClaw 测试、`pnpm lint`、`pnpm typecheck` 和受影响回归；触及跨包合同再运行完整 `pnpm test`。真实联调以独立测试 Gateway 和线上测试 IM 环境进行，不改用户既有实例策略；分别记录直连 Gateway、CLI/原生 SDK、IM 投递，不用一项成功代替其他项。

README 和 OpenClaw 规则同步记录“源码审查/严格 fixture/真实联调”三个证据层级、支持标签、权限限制与未知版本行为。当前所有 M0–M4 实施项均未执行，只有本轮调研和旧创建 Schema 的本地校验已完成。
