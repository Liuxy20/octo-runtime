# 口径与结论

2026-10-20：用户撤回公共层原生实现，Go/Job 方案不再实施。**以下 95 分仅是旧方案的历史自评，已不适用于当前交付范围。** 当前交付 Gateway drain 和 Node.js 生命周期修复，不宣称 Windows 强杀/父先退缺口已补齐；不能通过保留旧评分使未完成目标看起来达到 95 分。现行边界见[架构约束](../../rules/architecture.md#实现语言与原生依赖边界)。

旧方案可完成性 **95/100**。这是单次工程自评，不是成功概率、实现完成度、独立评审结论或平台验收成绩。
95分的依据是修复责任、信号/时序、原生机制、文件落点、发行路径和失败测试均有明确下一步；
不是因为预先把尚未执行的 M0 或 Windows 验收记成通过。产品实现尚未开始。

## 保留的 5 分

1. **原生 IPC 适配，2分。** Win32 Job 与挂起关联有官方依据，但 broker 透明保留 Node24/libuv 的 fd3/CRT映射、exit/close/disconnect 尚需原型。M0以W01/W02/W05/W06为必过门；失败先修 launcher，不能降级普通 spawn 或跳过 IPC。
2. **受限 Windows 宿主，1分。** 企业策略/外层Job/桌面与CI会话可能限制嵌套。W07要求拒绝可观察、无残留；Windows10/11实际环境补证据，不能以OS理论替代。
3. **真实收尾投递，1分。** 3秒业务drain内的线上ACK和Provider取消尾事件受延迟影响。G05/G06/I04以有界且真实的 incomplete 为可接受失败行为；不承诺离线必达，不能无限加时。
4. **原生资源分发，1分。** Go交叉编译可覆盖x64/arm64，但杀软、架构和消费安装行为需最终tgz测试。W10在无编译器/无网络环境验证；构建缺资源立即失败。arm64缺机器保留未验项。

## 评分复核约束

- 任何方案变更导致 Node IPC 不能保持、公共 SDK 必须新增 Windows 参数、Job 归属存在执行窗口，技术分降至不超过20，总分低于95；先回到M0补设计。
- 任何计划删除 leader先退、owner死、兄弟隔离、最终投递失败或最终tgz检查，验收分降至不超过20，总分低于95。
- #65/#66 合并后若引入不同关闭/存储所有权，必须重做C01–C06映射及G03/G09，不能沿用此评分直接声明无冲突。
- 缺少某平台结果是实施阶段未完成，不是把计划分数改写成验收分数的理由；对应 P1 不能在必需证据缺失时关闭。
- 本轮未调用子Agent；此分数不标记为多人复核。后续实际评审必须保留原始发现和复核结果。
