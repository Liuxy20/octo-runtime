## 用户确认的原始 ACP 错误详情

PR #216 评审指出 stopReason 可为数字/对象，直接 toLowerCase 会抛类型错误。新增类型检查及回归；只读取已有 ACP 失败信号，成功结果带 _meta 不算失败。

用户明确要求错误码对应公共消息，后面直接拼原始 _meta 的 JSON，不解析、不脱敏、不筛字段。实现删除 CodeBuddy 私有错误分类与 providerError 投影，登记 `ACP_MODEL_REQUEST_FAILED` → `OH-PRV-4010`，message 为公共消息加换行及 JSON.stringify(原始 _meta)。Core 对此码原样保留消息，其他错误行为不变。66 项专项、全量 Node 2078 通过/56 跳过及 WebUI 35 通过，构建/类型/静态/文档检查通过。完整验证结果见[追加记录](../../tasks/202-203-codebuddy/validation.md)。

## 修正原文保留的范围

后续评审发现上述实现将整个 ACP 错误 payload 豁免于脱敏，超出了用户只保留 message 原文的要求。新增测试在旧实现复现外层字段泄漏，再将 message 与外层字段分离：仅字符串 message 原样返回，外层继续原有公共脱敏，自定义 Adapter 使用相同错误码也不能绕过。原始 _meta 不解析、不裁剪，内容完整保留。

专项 67 项通过；全量 Node 2094 通过、56 跳过，WebUI 35 通过。类型/构建、lint、命名、改动格式、OKF 和 diff 检查通过，边界与复现证据见[验证记录](../../tasks/202-203-codebuddy/validation.md#acp-消息原文例外的范围修正)。
