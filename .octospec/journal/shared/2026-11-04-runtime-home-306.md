# Issue 306：Home 所有权

Home helper 的正确性不能代替启动边界的正确性：原版本 componentEndpoint 可将空字符串变成 cwd 地址，hostHomePaths 不检查存在，原公共 KernelService 在显式 stateDirectory 指向不存在 Home 时实际创建根并启动。没有发现父目录回退，不把未发现的行为写成事实。

修复将 Home 选择与根准备归还宿主；两个公共服务必填 home，在原 initialize/cause/cleanup 链前置校验。CLI 单独选择 --home 或统一 ~/.octo-runtime。身份辅助函数的路径对象也保存 home，写入前重验，缓存对象不能重新创建消失的根。路径计算与实际存在/权限验证分开；endpoint-only 连接/租约不推断 Home，但必须验证实际地址。

可复用约束已进入 [生命周期规则](../../rules/runtime-lifecycle.md#runtime-home-所有权与启动校验)、[架构签名](../../rules/architecture.md#createkernelservice-目标签名)和[本地传输](../../rules/local-execution.md#playboard-临时端点与常驻-home)。公开迁移与来源见 [Home 参考](../../../docs/zh-CN/reference/runtime-home.md)。

验证中的平台计算、真实文件系统/ACL、真实管道与完整回归分别记录。Windows 本机允许某些超出文档合同的 pipe 名，不据此推导跨版本支持，也不把泛化 EACCES 猜成纯长度错误。Unix 的真实 getconf/bind、外部 Electron 与在线 Provider 没有用 Windows 合成参数冒充通过。具体命令、失败和后续复核以 [验证记录](../../tasks/306-runtime-home/validation.md)为准。
