# Issue 101 实施验证

需求、完整英文提示与边界见[任务简报](../../tasks/101-bot-mention/brief.md)。基线为最新远端 `main@102fb9c`，分支为 `research/issue-101-mention`。

## 行为与边界

- Gateway 在请求装配时将默认英文 mention 控制指令追加在宿主本轮有效 `entries` 后，构造唯一 `octo.control/instructions` item。ExtraSet 中显式配置的指令属于宿主内容，在前保留；顺序、重复内容和宿主空白均保留，不修改输入或累计旧人设。
- 静态/动态宿主人设仍按原规则替换，公共 Context 合并与 mandatory 合同保持原语义；新默认只属于 Octo Gateway，不进入 WeCom 等其他 Extra。
- 默认控制规则带 `[OCTO_CHANNEL_MENTION_RULES_V1]` 边界，整段及每轮普通 Context 短提醒均为英文。逐轮提醒覆盖已有 Provider binding，不自动 reset。
- 用户授权的交接可将明确 `robot=1/true` 的当前 Bot 成员转换为原生 mention；真人继续接受 `robot=0/false`。保留 Markdown 结构排除、广播 UID 拒绝、成员核验和查询失败时的纯文本降级。
- 发送沿原连接携带可读正文及准确 UTF-16 entities；不增加 CLI 发送或模型重跑。接收 Bot 仍须明确允许发送 Bot 并通过原有准入。
- 自消息拒绝位于命令、Context 准备和 AgentRun 调度前。自己 @ 自己、AI 广播或自己列入 allowed_sender_ids 都不能绕过，覆盖私聊、群和话题。该行为原本已有，本轮补充明确注释、针对性回归和 Octospec 强制约束。
- 默认控制指令计入原 32 项 / 64 KiB 预算，不静默丢弃控制指令或显式业务项。两个既有项数预算 fixture 调整一项，为新增必需控制 item 留出位置，仍验证原有自动历史降级。
- 按用户明确要求，compaction 保留交给模型遵守英文提示，不新增保留机制、不触发或验证模型 compaction。

## PR #105 P2 冻结重试修复

评审指出默认指令在卡片重试时重复追加。该问题成立：同代次卡片重试从 occurrence 读取的 `saved.contexts` 已是完整组合产物，原实现再次调用 `createImInvocation` 时按宿主原始输入处理。结果是规则累计，接近 64 KiB 的合法快照会在重试准备时超限，无法进入第二次 Kernel 调用。

修复沿用现有内部 `historyRetry` 来源标记，仅在新准备的轮次追加渠道默认规则。重试仍校验并复用冻结 Context；不扫描提示词、不按文本去重，宿主显式重复规则保持原样。双语 Extra 指南和 Channel 约束已补充冻结重试边界。

验证先增加 HG-19 完整 Context/inputs 比较、连续两次重试、宿主两份相同规则及群/话题近预算重试，旧代码三项均失败，复现重复追加与重试未到 Kernel。修复后四个定向文件 51 项通过；扩展到全部 IM 与 Gateway 会话存储/排空回归共 314 项通过。Gateway 构建、全仓 TypeScript 与 ESLint、修改文件 Prettier、4 项文档测试及 Octospec 元数据/链接校验均通过。远端检查与评审以 [PR #105](https://github.com/Mininglamp-OSS/octo-runtime/pull/105) 当前状态为准。

## PR #105 Windows CI 关闭测试修正

[CI 39776544216](https://github.com/Mininglamp-OSS/octo-runtime/actions/runs/39776544216) 的唯一矩阵失败为 Windows / Node 24 的 `Windows SDK preserves the final log near the full drain bound: incomplete=false`：尾日志缺失，约 3.82 秒返回；同轮其余五个平台组合通过。该 fixture 将尾日志写入阻塞 950 ms，而 `RuntimeLogging.close()` 原有超时为 1000 ms，包含线程调度、实际文件写入及完成通知，仅有 50 ms 余量，无法稳定表达成功排空前提。日志本身按既有合同允许超时丢弃。

调整仅涉及测试：执行器关闭人工延迟由 2490 ms 改为 3200 ms，日志写入延迟由 950 ms 改为 250 ms，总延迟仍约 3.45 秒，继续覆盖已确认关闭后的较长排空窗口。保留完整尾日志、真实日志线程、执行器 incomplete、清理因果顺序、清单保留及五秒上限断言；尾日志失败额外输出完整 trace 以区分日志超时与父进程提前回收。生产关闭预算、日志可丢弃语义及 CI 门禁均不变。新的本地与远端验证另行记录。

本地验证：44 项 Kernel/Host 生命周期、监督、RPC 与日志回归通过；Windows 专项文件在 macOS 上按原有条件跳过 22 项，不作为 Windows 通过证据。双语文档及 4 项文档行为测试、修改文件 Prettier、`git diff --check` 和 Octospec 检查（325 单元、20 规则、2385 链接）通过。远端 Windows 24/26 及完整 CI 矩阵须在新提交上重新验证。
